# Load Once, Refine In-Cache：第一阶段验证

本轮回答一个问题：在同样的专家缓存字节数下，保留每个 token 的首轮专家，是否比直接扩大静态热门池更划算？这是第二阶段补偿训练与真机 offload 的入口实验。当前不能把路由命中率或逻辑搬运次数称作延迟收益。

## 可重复运行

固定入口为 `bash scripts/run_experiment.sh`；配置在 `configs/experiment.json`，环境和下载分别由 `scripts/setup_env.sh`、`scripts/download_assets.sh` 准备。复用服务器已有的 `$HOME/loop-moe-env/bin/python`，已有 PyTorch CUDA；其余依赖见 `requirements-gpu.txt`。首次设置可先指定 `PYTHON_BIN=/path/to/cuda-env/bin/python`。不要在 MacBook 上运行入口。运行会检查服务器 GPU 进程、显存和利用率，获取共享 GPU 锁；没有空闲卡则退出。

本轮登记实验后，以调度器提交固定入口：

```bash
orx exp run 0e865b08-5d83-4088-999e-949b5776b109 --backend ssh --host pku_pro5000 --no-container
```

下载默认使用 HF 镜像，模型与数据缓存继续使用 `/data1/shared/$USER`。xLLM 源码固定为 `755c7b3a91081fe0f83500eabd53bd2490b8b745`。输出写入远程 `loop-research-runs/<run-id>/`，包含切分、每条样本结果、验证集选择和完整汇总。源码由提交快照传输。

## 对照与公平性

- IFM Ouro-MoE 原生 4 轮、Huginn-MoE 原生 8 轮。保持原始 router 的 sigmoid/softmax、偏置、选后归一化和缩放语义。
- 原生精确路由 + 静态热门缓存；首轮专家 ID 重放；首轮建集 + 热门池内晚轮路由；不保留首轮集合、直接扩大热门池的晚轮路由。首轮重放只复用 ID，权重按当前轮重新计算，不能直接等同 ELR 的 ID+权重重放。
- 缓存为 1.98 / 3.99 GiB，以真实 BF16 专家字节数向下取整。所有策略都预留一个顺序拷贝暂存槽。Load Once / replay 额外预留每个循环物理层两个槽，直到当前 token 完成。热门池按校准集的全局频率分配；hot_late 保证每个循环池至少两个可选热门专家。
- 不使用整段 prefix 的首轮专家并集。每个 token 只能使用自身该物理层首轮选出的两个专家，避免偷看未来 token 和超预算。
- 首次访问每个物理层始终精确路由。Huginn 的 prelude/coda 不施加晚轮约束。
- 晚轮逃逸门槛为池外候选相对池内第二名的 log gate-score 优势，分别测试 0.02、0.1、0.5、近似无穷；逃逸专家只占暂存槽，不扩张持久集合。全程走受约束模型自身轨迹，不重放教师未来路由。

## 数据与判断

沿用已有文档分区器，校准 16、验证 24、训练预留 128、测试 64 条，长度 256；混合 WikiText 和 HumanEval 代码。热门集合只用校准集。验证集在逻辑搬运至少减少 30% 的选项中选 NLL 最低者，锁定后才测测试集。所有固定网格也记录测试曲线，但后续训练配置不得据此回头选点。NLL 按序列配对 bootstrap；同文档可能产生多块，所以这些区间仅作为筛查，正式确认须扩大独立文档数并按文档聚类。

原生、首轮重放、两个预算分别选出的 Load Once / hot_late 会额外评测同一组 128 道 ARC-Challenge，记录逐题正误，不能把这个规模下几 pp 的变化判成显著。该阶段不跑 GSM8K/MBPP 生成，不将代码 NLL 叫作 pass@1。

内部筛查门槛：

1. 若测试 NLL 增量上界不超过 0.02 nats/token，同时逻辑搬运下降至少 30%，进入真正 offload 验证。
2. 若存在节省搬运的选项但 NLL 损失较大，进入受限的 500 步补偿试验。比较无补偿、共享 LoRA、共享基底加稠密逐轮核，并加无缓存约束的同预算适配对照。适配器及基底也必须扣除缓存预算。不能仅靠免训练掉点就否定补偿方向。
3. 若保留首轮集合挤占热门池后连逻辑搬运都不减少，应优先止损原调度设计。若仅 hot_late 胜出，应收缩为通用缓存感知路由，不宣称首轮复用有特殊收益。
4. 最终 go 仍须实际 offload、同样 KV 引擎、交错策略顺序、配对重复的端到端 TPOT 至少改善 5%，且质量损失可接受。当前全驻留质量实验不会输出 TPOT。

## 需要纠正的原论证

共享物理权重是复用的必要条件，不能推出无损 R 倍复用；梯度能量集中也不能推出冷专家可删除。现有 ELR 已测试首轮路由重放，创新点必须落在严格缓存预算、质量恢复与真实卸载收益。原方案承诺的 87–90 ms/token 尚未验证，不作为本轮结果或 ETA。
